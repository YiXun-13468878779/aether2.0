## 产品目标

Aether 是一个以自由创作和作品交流为核心的 AI 产品。保留 Aether / 灵魂对话的品牌，以及安静、深色、带宇宙感的空间气质。

主路径：进入对话 → 自然出现创作邀请或用户主动创作 → 画布/上传 → 作品留在身边继续交流 → 修改、创作另一幅，或结束这次相遇。

AI 的观看应结合整体、多个具体细节和此前对话；可以提出有想象力的独立见解，但不能把自己的解释当成作者真相。用户纠正后应改变理解。避免反复二选一、固定反馈按钮、只抓一个细节和模板化报告。保留“少问”和“不要问”的区别。

先打磨核心体验，登录不作为首次体验的门槛。作品和旅程的云端保存仍需单独完成；不能把登录、数据保存、限流混成一个功能。

## 第一批代码改动

1. 修复新建/复制画作时，旧数组覆盖刚保存笔迹的问题。使用函数式状态更新；复制操作读取当前画布快照。
2. 保存时立即读取当前 PNG，移除延迟回调读取另一幅画布的竞态；图像恢复使用递增代号并检查画布身份，阻止晚到的加载覆盖新画。
3. 后续普通对话同样把近期作品图片传给模型；图片在发送前缩小，不把画布原始大图直接塞进每次请求。
4. 控制器失败返回明确错误，空模型流不再伪装成成功；添加停止回应、请求取消和输入法合成保护。
5. 首页加入实际 HTML 标题和游客入口，提供主动创作/上传入口，登录仍可选。系统字体避免构建时依赖外部字体服务。
6. 提供旅程 JSON 导出/导入和离开提醒。当前预览数据只在会话内暂存，刷新前需要导出；这不是云端存储的最终实现。
7. 接口添加请求大小限制、同源检查和预览级限流。内存限流只在单实例生效，不能替代正式共享配额。

## 环境说明

- DASHSCOPE_API_KEY：模型服务密钥，仅通过 Vercel 环境变量管理，不写进源码或聊天。
- QWEN_MODEL / QWEN_BASE_URL：沿用现有模型与接口配置。
- AETHER_REQUIRE_LOGIN=true：要求模型请求登录；省略或 false 时允许游客体验。公开上线前需要完成共享限流、额度管理和云端保存。
- NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY / CLERK_SECRET_KEY：可选登录配置；两者缺失时，游客体验仍应可用。
